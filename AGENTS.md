# Temba — Agent Memory (full scope)

This repo is **`temba-user-only`**: the public **web app** for ticket buyers. It is not the mobile app, not the organizer console, and not the admin app. Those live in other repos.

Read this before changing product, payments, events, SEO, or database-related code.

---

## What Temba is

Temba is the **n°1 online ticketing platform in Burkina Faso**, expanding across Francophone West Africa and the diaspora.

- **Site:** https://tembas.com
- **Product:** Discover events → buy tickets in **FCFA (XOF)** → QR e-ticket on phone
- **UI language:** French
- **Positioning:** local payments (Orange Money, Moov Money, card), local support, ticket transfer
- **Brand line (BF print):** “100% Burkinabè” — do **not** use this on CI/SN/diaspora materials
- **Tagline:** Découvrez – Réservez – Profitez
- **Support:** support@tembas.com · +226 74 75 08 15
- **Google Play account-deletion URL:** https://tembas.com/account-deletion

**Logo:** geometric white **T** + red disc on Temba blue. Wordmark **Temba** must stay more prominent than the word “Billetterie”. Print QR codes must be smart links (app / store / web fallback).

**Markets (in order):** Burkina Faso (Ouagadougou, Bobo-Dioulasso) → Côte d’Ivoire → Senegal → France diaspora → Mali/Cameroon only when there is real event supply.

**Traffic reality:** Burkina SEO alone will not hit 1M visits/month. That number needs multi-country supply + WhatsApp/Facebook + organizer backlinks. **Do not drop Netlify** to chase traffic. Hosting is not the bottleneck.

## Non-negotiables

1. **Do not write or deploy database migrations** unless the user explicitly asks. Schema, RPCs, and RLS are already live. Frontend **fetches and displays**. If an RPC fails, add a graceful fallback (direct table query or existing checkout path). Do not “fix” SQL by shipping a migration unasked.
2. **Do not rebuild working Edge Functions.** Payment webhooks (`stripe-webhook`, `pawapay-webhook`) were built and tested. Surgical additions only (Redis dedup, QStash, `payment_finalize_jobs`).
3. **Do not rewrite the app to Next.js** unless asked. Crawler HTML is handled by `netlify/edge-functions/og-tags.ts`.
4. **Do not drop Netlify** as an SEO/scale strategy.
5. **Never `new Date("YYYY-MM-DD")`.** Use `parseLocalDate` from `src/utils/formatters.ts` or you will show the previous day.
6. **Do not push to `main` unless the user says “push code”.**
7. **Do not invent backend columns.** If a query 400s, the column/relationship likely does not exist — query separately, do not join across missing FKs.

## Domain model (buyer-facing)

### Events
- Table `events`. Status for public: `PUBLISHED`. Soft delete: `deleted_at`.
- `featured` floats cards to the top of attractions lists.
- URLs today: `/events/:uuid` (slugs are a future SEO job, not implemented).
- Geo: `country_code`, `city`, `timezone`, `address`, `region`. Default TZ `Africa/Ouagadougou`.

### Two event kinds
| Kind | Flag | Booking UI |
|---|---|---|
| One-date / festival | `is_permanent` false/null | `BookingForm` + date list from `event_dates` |
| Attraction (zoo, park, museum, water park…) | `is_permanent = true` | `PermanentBookingPanel` + `VisitDateCalendar` |

Permanent events: `attraction_type`, `sales_start_date`. Dates generated by backend (`generate_permanent_event_dates` / schedule). Public RLS **must** allow `status = PUBLISHED` including `is_permanent = true` (mobile hit this bug).

**RPCs (already exist):**
- `get_permanent_schedule`
- `check_visit_date_available`
- `initiate_permanent_purchase` (if it fails — missing `pgcrypto` / JSON scalar — **fall back to `/checkout` with state**)
- `calculate_service_fees` (ambiguous column — frontend has table fallback)

### Discovery entities (slug URLs)
- Organizers: `/organizers`, `/organizers/:slug` ← `organizer_profiles` (`organizer_id`, `verification_status`, not `user_id` / `verified`)
- Artists: `/artists`, `/artists/:slug` via `event_artists` + `artists`
- Venues: `/venues`, `/venues/:slug`
- Tags: `/tags/:slug`
- Attractions directory: `/attractions`
- City landings: `/ouagadougou`, `/bobo-dioulasso`, `/abidjan`, `/dakar`
- Categories: `/categories`, `/categories/:categoryId`

Do **not** join `organizer_profiles` or `event_artists` in the main `events` select — no FK relationship. Fetch in separate queries (see `EventDetails.tsx`).

### Venue services & food
- Venue-wide + event add-ons: RPCs `get_venue_services`, `get_event_addons`. Wrapper: `venueServiceService.ts`. Checkout math: `addonService.ts`. UI: `AddonSelector`.
- Food menu: RPC `get_event_food_menu`. Wrapper: `foodMenuService.ts`. UI: `FoodMenuSelector`.
- Hide the section if there are no **active** services / no **available** items.
- On permanent confirm step, selectors are collapsed by default.
- **Checkout total:** extras must reach the payment form. `PermanentBookingPanel` navigates with `addonTotal` + `isPermanent`. `Checkout.tsx` **seeds** `addonsAmount` from `state.addonTotal` and hides selectors for permanent bookings. `CheckoutForm` / `GuestCheckoutForm` add `addonTotal` into `grandTotal`. If you drop this, food/service money “gets lost”.

## Payments (do not break)

**Default method: Orange Money.** Then Moov Money, then card.

Flow:
1. User pays (PawaPay deposit or Stripe).
2. Webhook (`pawapay-webhook` / `stripe-webhook`) marks payment complete.
3. Tickets created via `admin_finalize_payment` and/or `finalize-order`.
4. Safety nets: Redis status, QStash, table `payment_finalize_jobs`, function `process-finalize-jobs`, `check-pawapay-status`.

If inline ticket insert fails, **upsert** `payment_finalize_jobs` — never return 200 and drop the tickets.

WhatsApp booking: sibling adapter, not this repo. After tickets exist, `finalize-order` may POST `WHATSAPP_ADAPTER_URL/paid` (optional secret). See `docs/WHATSAPP-CHECKOUT.md`.

Guest checkout: same `tickets` / QR as accounts; retrieval is `guest_orders.token` + `lookup-guest-tickets`. Mobile engineers: **`docs/MOBILE-GUEST-CHECKOUT.md`**. Permanent attractions on web skip `initiate_permanent_purchase` and go through checkout with `eventDateId` + `addonTotal` (auth-before-pay is no longer required on web).

Service fee: `useFeeCalculation` / `calculate_service_fees` with fallback. Guest form uses a 2% fallback in places — do not “unify” without asking.

## Design rules

- Match existing Temba UI: cream grain, brand blue CTAs, accent gold for conversion, rounded-xl2 cards, `eyebrow` labels, tabular nums for money.
- Format money with `formatCurrency`.
- French copy. Informal-polite. No English UI unless the page is bilingual on purpose (`AccountDeletion`).
- Mobile: no horizontal page scroll. Attraction calendar and homepage strips must fit the viewport (snap-scroll on home attractions is OK).
- Logos: Orange / Moov / Visa / Mastercard already exist in `public/`. Do not replace with random images.

## Known traps

- `events.categories` column does not exist — use `event_category_relations`.
- `event_dates_times` table does not exist. `event_dates.display_order` may not exist. Select `id, date, start_time, end_time, status, capacity`.
- Gallery: `event_images`; URL column may be `image_url` / `url` / `src`. Order by `display_order` with fallback to `created_at`.
- `get_permanent_schedule` may 400 on GROUP BY — fallback in `permanentVenueService.ts`.
- Homepage `HeroPosterMosaic` must not format `event.date` for permanent events (null date → `Invalid time value`).
- Dashboard “Mes billets” → `/profile/my-tickets`.
- Filter dropdowns in overflow parents: use a portal (`createPortal`) + `position: fixed`.
